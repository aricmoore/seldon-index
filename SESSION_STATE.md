## Decisions made and why

1. **Recommended against literal "fuzzy search + select from results" for File a Wire.** Why: there is no corpus to search against — every headline is invented at submission time and judged live, not pulled from an existing set. A real fuzzy-search feature would need a different data source entirely (e.g. Federal Register signal titles as autocomplete seeds); user didn't ask to pursue that.
2. **Delete access = anyone/any row; index behavior = hard delete + recompute.** Not my call — these were presented as an explicit two-question fork via `AskUserQuestion` because the app's lack of any auth model and its snapshot-based event storage made both directions genuinely defensible; the user picked both explicitly.
3. **Added a `window.confirm()` guard on delete, unprompted.** My own design call, flagged in the plan rather than silently added: this is the one destructive, irreversible, whole-room-visible action in an otherwise confirmation-free app, so one click of friction seemed worth it even though it's an inconsistency with the rest of the UI. User approved the plan as-is without pushback, so treat this as accepted unless they say otherwise.
4. **Reused `HEADLINE_RATE_LIMITER` with a new `routeKey` instead of provisioning a new Cloudflare rate-limit binding.** Kept the whole feature self-contained to application code, no `wrangler.jsonc`/infra changes, while still giving the new unauthenticated-delete route its own independent 5/60s bucket rather than sharing consumption with headline submissions.
5. **Extracted `replayEvents()` as a shared helper used by seeding, submitting, *and* deleting**, rather than writing delete-specific recompute logic in isolation. This is why a "just add a delete button" task also touched `handlePostHeadline` and `buildSeedState` — kept all three accumulation call sites from silently diverging over time.
6. **Omitted the Claude/Anthropic co-author trailer on this commit too.** Same standing repo-specific rule as last session (see memory), reapplied without needing to be told again.
7. **Included the already-pending `SESSION_STATE.md` edit in this feature commit** rather than leaving it uncommitted or splitting it out, matching the pattern already established in this repo's history.
