## Task 2: full-app audit plus fixes (this session)
Ran a full functional audit of the whole app (every file in `worker/` and `src/`, both `tsc` configs, `wrangler.jsonc`) at the user's request. Found 8 issues, ranked by severity. User said "yes" then "go for it," so all 4 actionable items are fixed; the remaining 4 are informational/by-design, not code changes.

1. **[FIXED] No rate limiting on cost-bearing public endpoints.** `POST /api/headline` (calls the headline classifier) and `GET /api/fellow-watch` (calls GovInfo plus regulations.gov) had zero throttling, so anyone could script either into real API cost/quota burn. Added Cloudflare's native Rate Limiting binding: `wrangler.jsonc` now has a `ratelimits` array (`HEADLINE_RATE_LIMITER`: 5 requests per 60s, `FELLOW_WATCH_RATE_LIMITER`: 10 requests per 60s, both `namespace_id`s picked fresh as `1001`/`1002` since the account had none before). Verified live against local `wrangler dev`: 6 rapid `POST /api/headline` calls returned `200, 200, 200, 200, 200, 429`, exactly matching the configured limit of 5. `wrangler types` was re-run to regenerate `worker-configuration.d.ts` (gitignored, not part of the tracked diff) with the two new `RateLimit`-typed bindings.
2. **[FIXED] Classifier-outage fallback bypassed all content moderation.** `classifyWithFallback()` in `worker/index.ts` previously set `valid: true` unconditionally whenever the classifier call threw (rate limit, outage, bad key), meaning spam or garbage would sail through onto the live wire with zero gating during any outage. Added `looksLikePlausibleHeadline()` to `worker/scorer.ts` (exported, requires 3 or more alphabetic words) and wired it into the fallback: implausible headlines now get `valid: false, impact: 0` with rationale `'too short to evaluate (classifier unavailable)'` instead of being auto-accepted. Deliberately kept the bar low (word count only) so legitimate short-but-real headlines during an outage still get through; this closes the "anything at all passes" gap without acting as a full moderation replacement.
3. **[FIXED] CSS specificity bug**: `.wire-form-name`'s `flex: 0 0 160px` was silently overridden by the higher-specificity `.wire-form input { flex: 1 }` rule, so the "Filed by" field never actually stayed a fixed 160px, it grew and shrank like the headline field. Fixed by upgrading the selector to `.wire-form input.wire-form-name` (`src/styles.css`).
4. **[FIXED] Duplicate keyword**: `'lawsuit'` was listed twice in Frontier Legal Defense's keyword array (`worker/categories.ts`). Harmless, but removed the redundant second entry.
5. **[Not changed, flagged only] Rejected submissions still share the 200-event cap and the 25-row Wire Tape view with live ones.** Same open item as an earlier session's item (b), see Open Questions below. Needs a product decision, not a one-line fix.
6. **[Not changed, informational] Fellow-mentions total API failure is indistinguishable from "genuinely zero mentions" in the UI.** `buildFellowMentions()` swallows all per-fellow errors and returns an empty list rather than surfacing a broken-versus-empty distinction. Low priority since GovInfo/regulations.gov being fully down for all 6 fellows simultaneously is an edge case.
7. **[Not changed, informational] "SESSION HIGH/LOW" label is misleading.** It's computed from the full stored roughly-200-event history including seed data, not values seen since the tab opened. Cosmetic/naming issue only.
8. **[Not changed, informational] Valid "Other"-category submissions move the total index but never appear in any Sector Board row.** By design, since there's no "Other" sector row, but worth knowing it means sector-sum does not equal total-index-movement.
